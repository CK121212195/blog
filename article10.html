仮想環境（venv）の作り方と必要性：プロジェクトごとの環境分離

Python初心者を脱却し、中級者へステップアップする上で絶対に避けて通れない概念が「仮想環境（Virtual Environment）」です。これを理解せずに色々なプログラムを作り続けると、いずれ必ず「環境が壊れて動かなくなる」という悲劇に見舞われます。

なぜ仮想環境が必要なのか？（依存関係の地獄）

例えば、あなたが「プロジェクトA」というWebアプリと、「プロジェクトB」というAIアプリを同じPCで作っているとします。プロジェクトAは「ライブラリXのバージョン1」を必要とし、プロジェクトBは「ライブラリXのバージョン2」を必要としている場合、PC全体のPython（グローバル環境）にインストールすると、バージョンが衝突してしまいます。

アップデートした途端に古いプロジェクトが動かなくなる現象を「依存関係の地獄」と呼びます。これを防ぐために、プロジェクトごとに独立した「Pythonの小部屋（仮想環境）」を作るのがベストプラクティスです。

標準ツール「venv」の使い方

Python 3系には、仮想環境を作るためのツール venv が標準で組み込まれています。

  1. 仮想環境の作成： ターミナルでプロジェクトのフォルダに移動し、python -m venv myenv（myenvは好きな名前）と実行します。これでフォルダ内に小部屋の元が作られます。
  2. 仮想環境の有効化（アクティベート）： 使う前に「今からこの小部屋に入る」という宣言が必要です。Windowsなら myenv\Scripts\activate、Mac/Linuxなら source myenv/bin/activate と入力します。

ターミナルの左端に (myenv) のように名前が表示されれば成功です。この状態でpip installを行えば、その小部屋の中にだけライブラリがインストールされ、他のプロジェクトに影響を与えることは一切ありません。作業が終わったら deactivate と打つと小部屋から出ることができます。
